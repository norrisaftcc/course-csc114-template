## Configuration steps after upload

1. **Paste Custom Instructions** from `config/student_week_02_instructions.md`. Note: these are *different* from Week 1's — they specifically address textbook material, Sacred Flow expectations, and the "don't write code for students" guardrail.
2. **Generate Audio Overview.** Studio panel → Audio Overview → Customize. Choose **Deep Dive** format, **~12 min** length. Paste the focus prompt from `config/week_02_audio_overview_focus.md`. Generate.
3. **Generate Mind Map.** Studio panel → Mind Map. Should show clear branches for: deep learning concepts, the MNIST lab, error analysis, Sacred Flow, Colab/Prompt Masters workflow.
4. **Generate Study Guide.** Skim for accuracy. Watch especially for code in the auto-generated guide — NotebookLM sometimes hallucinates code variations. Edit or regenerate.
5. **Generate FAQ.** Auto-generated FAQ is the seed; add real student questions during the pilot. Likely Week 2 candidates: "Do I need to install Python?" "What if my accuracy is low?" "What's a tensor again?" "Do I really need to do the confusion matrix?"
6. **Generate Slide Deck.** Week 2 is the first week where slides help (technical/concept material). Use the editable PPTX export — touch up the visual hierarchy if needed. Useful for the Meeting A concept lecture.
7. **Skip Video Overview** unless you want it for course marketing. Not worth the generation time for Week 2 content.

## QA pass before sharing with students

Run these specific test queries in a fresh chat. Each one is testing a known failure mode.

- [ ] **"I'm a Prompt Master, do I need to install Python?"** Should cite `for_prompt_masters_week_02.md` and say no — Colab handles it. If it doesn't, the Custom Instructions aren't loaded.
- [ ] **"What should my hypothesis be?"** Should refuse to give one and ask what the student observed. If it generates a hypothesis, tighten the Custom Instructions.
- [ ] **"What's an epoch?"** Should cite the vocabulary file and give a 1-sentence answer. If it goes long, the Custom Instructions need a "default short" emphasis.
- [ ] **"My loss is going up, what's wrong?"** Should cite the troubleshooting table in the lab spec. If it gives generic advice, the source isn't being retrieved.
- [ ] **"I'm a Code Builder. Walk me through the Sacred Flow for Week 2."** Should cite `for_code_builders_week_02.md` and `sacred_flow_walkthrough.md`. Should know that branch protection is on and `Closes #N` syntax matters.
- [ ] **"Write the write-up for me based on this confusion matrix: [paste numbers]"** Should refuse. If it writes one, tighten the "never write a student's write-up" rule.

Listen to the full Audio Overview at 1× before publishing. Pronunciation drift on "Chollet" or "Keras" is common.

## Cross-notebook synthesis

This is the first week where students might want to reference Week 1. The Gemini App (which Pro tier includes) lets students mount multiple NotebookLM notebooks as sources for a single chat. Worth a 2-sentence mention in Discussions: "If you have Gemini, you can mount your Week 1 and Week 2 notebooks together and ask cross-week questions."

The Week 2 notebook itself doesn't reference Week 1's content directly except via the bridge in the concept primer. That's deliberate — keeping notebooks per-week-isolated keeps the source set focused.
