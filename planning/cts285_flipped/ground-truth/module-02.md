# 02 — Requirements and the Backlog

**Loop 1 · Pre-Sprint · Weeks 3–4 · 75 pts.** Role: Product Owner. From vague client
input to a prioritized backlog.

## ⬡ Before Class — Async

> **NTS Floor 1.** The vague client email arrives. Students decompose it, ask the
> right questions, and build the backlog.
> *"Client says 'I want a system that handles everything.' Students must negotiate scope."*

- D User Story Decomposition — 10 epic decomposition exercises · *MLO 2.2 · Dashboard: user-story-practice*
- D Estimation Practice Arena — 20 stories vs. Fibonacci expert estimates · *MLO 2.4 · Dashboard: estimation-practice*
- ▶ MoSCoW Backlog Sorting — drag 12 features into priority tiers · *MLO 2.3 · Sim*
- ▶ Functional vs. Non-Functional — classify 15 requirements · *MLO 2.5 · Sim*
- ▶ Elicitation Scenario — vague email, choose best follow-up questions · *MLO 2.6 · Sim*
- ▶ Acceptance Criteria Quality Checker — testable vs. vague · *MLO 2.1 · Sim*
- ▶ Plain Language Feature Description — client-validation sim · *MLO 2.7 · Sim*

**Lucidchart:** ◈ User Story Map — Data Man backlog by user journey & priority.

## ⬡ In Class — Facilitated

- 🎤 **Live Backlog Grooming Session** — Norris plays client. Students ask elicitation
  questions as a class. Scope negotiation live.
- 🗣 **MoSCoW Debate** — Small groups defend their priority decisions. Class surface
  where they disagreed and why.
- 🗂 **Story Point Calibration** — Norris runs a planning poker round on 3-4 shared
  stories. Teams compare estimates and reconcile.

**⚡ RSI Touchpoint:** Instructor annotates each student's submitted backlog in Canvas
— written feedback on acceptance criteria quality and MoSCoW justifications. Gates
Module 3. *Response window: 72 hrs · Platform: Canvas Comment · 🔒 Gates M3.*

### MLOs

- **2.1** Write well-formed user stories with GWT criteria · *Create · CLO 2*
- **2.2** Decompose epics into sprint-sized stories · *Analyze · CLO 2*
- **2.3** Prioritize backlog using MoSCoW with justification · *Evaluate · CLO 2*
- **2.4** Estimate story complexity using Fibonacci · *Apply · CLO 1*
- **2.6** Apply elicitation techniques to ambiguous requirements · *Apply · CLO 2*

## ⬡ After Class — Canvas Submissions

- **Data Man Product Backlog** — 15+ user stories with format, acceptance criteria, story points, MoSCoW with written justification · *60 pts · Rubric · 🔒 Instructor review gates M3*
- **Requirements Elicitation Reflection** — 200-word response to stakeholder scenario demonstrating elicitation understanding · *15 pts · Rubric*

## Thread & gates

- **Data Man Thread:** Full product backlog — 15+ stories, acceptance criteria, story
  points, MoSCoW. Becomes the sprint source for M3 and M4. ↳ *Deliverable: Full
  prioritized product backlog.*
- **Unlocks when:** M1 Mastery Check passed. **Gates M3 on:** Instructor annotates backlog.
